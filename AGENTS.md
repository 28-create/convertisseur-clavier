# AGENTS.md

Offline keyboard-layout converter: `convertisseur.html` (single-file web page, source of truth), `fix-presse-papiers.py` (Windows clipboard helper), `app.py` + `build_exe.py` (PyInstaller app), PowerShell installer. No server, no build step, no dependencies for the tests. Docs, UI text and commit messages are French.

## Source of truth and generation chain

- `convertisseur.html` is the only source of truth: the six mapping tables (`FR_TO_HE`, `HE_TO_FR`, `EN_TO_HE`, `HE_TO_EN`, `QW_TO_AZ`, `AZ_TO_QW`), `APP_VERSION`, UI and i18n all live there.
- The tables in `fix-presse-papiers.py` between `# <maps:generated>` and `# </maps:generated>` are generated from the HTML. Never edit them by hand.
- `version_info.txt` is generated by `gen_version.py` from `APP_VERSION`. Never edit it by hand.
- `index.html` is only a GitHub Pages redirect to `convertisseur.html`.

## Commands (run from the repo root — the scripts open files by relative path)

```sh
python gen_maps.py    # after editing maps in convertisseur.html
python test_maps.py   # table sync, duplicate key detection, known cases, fuzz vs reference
python test_page.py   # page integrity, i18n, JS syntax, WCAG contrast, version
```

- No test framework: both suites are plain stdlib scripts returning exit 0/1. Do not add pytest/unittest or new dependencies.
- Page and script must stay mirrors: `convert_smart` ⇄ `convertSmart`, `autodir` ⇄ `detectDir` (same 0.2 threshold, same accented-Latin class), `CAPS_SWAP` on both sides. `test_maps.py` regex-extracts `convertSmart`/`detectDir` from the HTML and runs them under `node` (silently skipped when node is absent): keep those exact signatures and keep a single inline `<script>` block, or the extraction breaks.
- `test_page.py` also pins: `REQUIRED_IDS`, exactly 7 `<fieldset>`/`<legend>`, no external http(s) resource, identical i18n key sets in fr/en/he, `APP_VERSION == latest git tag`, `version_info.txt` byte-exact, contrast selectors (`[hidden] { display: none !important; }`, `html[dir="rtl"] #settingsPanel.open`, dark-theme primary button).
- Any new UI string needs an entry in all three `I18N` languages (fr/en/he) and is used via `data-i18n*` / `t('key')`.

## Versioning / release

- `APP_VERSION` in `convertisseur.html` is the single version source; it must equal the newest git tag (format `vX.Y.Z`).
- Release flow: bump `APP_VERSION` → `python gen_version.py` → new `## vX.Y.Z` section in `CHANGELOG.md` → commit `Release vX.Y.Z : ...` → tag `vX.Y.Z`. User-visible changes also belong in `README.md` (French).
- Build (Windows only): `pip install pywebview pyinstaller` then `python build_exe.py` → `dist/ConvertisseurClavier-X.Y.Z.exe` (gitignored; WebView2 required). `python app.py` runs the page in a native window. Cannot be built or run on Linux.

## Platform conventions

- `*.bat` and `*.ps1` must keep CRLF (`.gitattributes`); everything else is LF. Do not renormalize.
- Comments and console output in `.py` / `.ps1` / `.bat` stay ASCII (Windows cp1252/cp1255 consoles crash on Hebrew/accents); non-ASCII is reserved for data, UI strings and the HTML.
- Two installer scripts, easy to confuse: `installer.ps1` (real install: Start Menu + `Ctrl+Alt+K` + uninstall entry) vs `installer-raccourci.ps1` (desktop shortcut only, `Ctrl+Alt+H`). `desinstaller.ps1` mirrors `installer.ps1`.
- `test_installer.ps1` is the end-to-end installer sandbox test (Windows only): `powershell -NoProfile -ExecutionPolicy Bypass -File test_installer.ps1`.
- CI (`.github/workflows/tests.yml`) runs `test_maps.py` + `test_page.py` on Ubuntu + Windows with Python 3.11/3.12/3.14, and the installer test on Windows.
