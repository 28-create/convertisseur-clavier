# AGENTS.md

Offline keyboard-layout converter: `convertisseur.html` (single-file web page, source of truth), `fix-presse-papiers.py` (Windows clipboard helper), `app.py` + `paste_watch.py` + `win32_clip.py` + `build_exe.py` (PyInstaller app and Ctrl+V watcher), `installer.iss` + `build_setup.py` (Inno Setup wizard), `extension/` (Chrome/Edge MV3 add-on), PowerShell installers. No server, no build step, no dependencies for the tests. Docs, UI text and commit messages are French.

## Source of truth and generation chain

- `convertisseur.html` is the only source of truth: the six mapping tables (`FR_TO_HE`, `HE_TO_FR`, `EN_TO_HE`, `HE_TO_EN`, `QW_TO_AZ`, `AZ_TO_QW`), `APP_VERSION`, UI and i18n all live there.
- The tables and `CAPS_SWAP` in `fix-presse-papiers.py` between `# <maps:generated>` and `# </maps:generated>` are generated from the HTML. Never edit them by hand.
- `extension/js/core.js` holds the same tables between `// <maps:generated>` + `// </maps:generated>` and a verbatim copy of `convertSmart`/`detectDir` between `// <core:generated>` + `// </core:generated>`, both generated by `gen_maps.py` from the HTML. Never edit those blocks by hand; the surrounding glue (`convertText`, `MAPS`, `DEFAULTS`) is hand-written. The extension has no build step: Chrome/Edge load it unpacked.
- The bigram models between `// <models:generated>` and `// </models:generated>` in `convertisseur.html` are generated by `gen_ngrams.py` (public-domain Gutenberg sources pinned by SHA-256). Never edit them by hand; adding a detection language = one `LANGS` entry + rerun.
- The Hebrew bigram model between `# <he_model:generated>` and `# </he_model:generated>` in `paste_watch.py` is generated by `python gen_ngrams.py --hebrew` (same Gutenberg source pinned by SHA-256). Never edit it by hand; the Latin page models stay untouched.
- `version_info.txt` is generated by `gen_version.py` from `APP_VERSION`. Never edit it by hand.
- `"version"` in `extension/manifest.json` is synced by `gen_version.py` from `APP_VERSION` (same single source).
- `#define MyAppVersion` in `installer.iss` (Inno Setup script) is synced by `gen_version.py` from `APP_VERSION`. Never edit it by hand; `build_setup.py --check` verifies version, high-resolution logo assets (`app.ico`, `installer-logo.png`), the Hebrew language, default-checked tasks, context-menu and watcher-autostart sections (no Inno needed), `build_setup.py` compiles the Setup on Windows. `app.ico` (multi-size) and `installer-logo.png` (1024 px) are rendered from `logo.svg`; the installer uses them for Setup/uninstall and the wizard.
- `app.py` embeds no mapping table: CLI verbs (`--convert-clipboard`, `--convert-file`, `--paste-watch`, `--paste-stop`, GUI preload via `preload_js`) reuse `fix-presse-papiers.py` loaded from the bundle (single logic source); clipboard I/O goes through `win32_clip.py` (Win32 ctypes, not tkinter).
- `index.html` is only a GitHub Pages redirect to `convertisseur.html`.

## Commands (run from the repo root — the scripts open files by relative path)

```sh
python gen_maps.py    # after editing maps in convertisseur.html
python gen_ngrams.py  # after changing LANGS (network, or --corpus-dir)
python gen_ngrams.py --hebrew  # regenere le modele hebreu de paste_watch.py
python test_maps.py   # table + CAPS_SWAP sync (HTML/PY/EXT), duplicate keys, known cases, JS↔Python fuzz
python test_app.py    # app.py : encodages de fichiers, injection du prechargement, verbes CLI
python test_paste.py  # surveillance : detection, modele hebreu, parite page, demarrage auto
python test_extension.py  # extension : manifeste, icones, CSP, cablage clic droit, conversions
python test_store.py  # paquet store : manifeste et limites du store, textes de fiche, zip
python test_page.py   # page integrity, i18n, JS syntax, WCAG contrast, version
python build_setup.py --check  # installer.iss coherence (version, context menu)
python build_extension.py --check  # paquet store coherent (version, fichiers references)
```

- No test framework: the suites are plain stdlib scripts returning exit 0/1. Do not add pytest/unittest or new dependencies.
- `app.py` must keep its contract with the installers: `preload_js` injects the file text after load (WebView2 rejects `file://...?text=...`, so never go back to a query URL), `read_text_file` must decode cp1255 (Hebrew ANSI) as well as cp1252/UTF-8, and the CLI verbs stay `--convert-clipboard` / `--convert-file` / `--paste-watch` / `--paste-stop` / positional file (test_app.py pins them).
- `paste_watch.py` must stay importable on Linux for CI: no `windll`, tkinter import or window creation at module load. The watcher intercepts only plain `Ctrl+V` (Shift/Alt/Win and all other keys pass through), marks its own injected events with `dwExtraInfo = MAGIC`, proposes only with a clear margin (`MIN_TARGET`, `MARGIN`, `SHORT_MARGIN`, `LAYOUT_MARGIN`), never changes the clipboard without an explicit choice, and uses the single-instance mutex / stop event. The popup exposes a compact AZERTY ▾ menu so the user can override the layout (preview and paste follow the choice), and stores the fallback for ambiguous short texts in `%LOCALAPPDATA%\ConvertisseurClavier\paste_watch.json` (`default_layout`, overridable with `CONVERTISSEUR_PASTE_SETTINGS` in tests); the tray menu exposes the same fallback. `win32_clip.py` is the only clipboard implementation shared with `app.py`.
- Page and script must stay mirrors: `convert_smart` ⇄ `convertSmart`, `autodir` ⇄ `detectDir` (same 0.2 threshold, same accented-Latin class), `CAPS_SWAP` (generated) on both sides. The extension gets the same functions copied verbatim by `gen_maps.py`, so it cannot drift. Tests regex-extract `convertSmart`/`detectDir` (test_maps.py) and `migrateSettings(stored, legacy)`, `histInput(text)`, `isHistDup(history, text)`, `normalizeForModel(s)`, `scoreLang(text, lang)`, `scoreReading(text)`, `suggestReading(text, currentLayout)` (test_page.py; reassembled in file order so declaration-order/TDZ bugs fail the tests) from the HTML and run them under `node` (silently skipped when node is absent). Keep those exact signatures, a single inline `<script>` block, and `gen_ngrams.normalize` mirrored with `normalizeForModel`, or the extraction/parity breaks.
- `test_extension.py` pins the add-on contract: MV3, `version == APP_VERSION`, content scripts `["js/core.js", "content.js"]` on `<all_urls>` + `all_frames`, minimal permissions (`clipboardWrite`, `contextMenus`, `storage`), no `host_permissions`, command `Ctrl+Shift+H`, PNG icons 16/32/48/128, no remote http(s) resource, no inline `<script>`/`on*=` in the popup (MV3 CSP), no `innerHTML`/`outerHTML`/`eval`, `node --check`, and mocked `chrome` APIs for the three context-menu entries and the keyboard command.
- `test_page.py` also pins: `REQUIRED_IDS`, unique ids, exactly 7 `<fieldset>`/`<legend>`, no external http(s) resource, a CSP meta, identical i18n key sets and placeholders in fr/en/he, `APP_VERSION == latest git tag` (hard failure in CI), `version_info.txt` byte-exact, closed settings panel `inert`, contrast selectors (`[hidden] { display: none !important; }`, `html[dir="rtl"] #settingsPanel.open`, dark-theme primary button).
- Any new UI string needs an entry in all three `I18N` languages (fr/en/he) and is used via `data-i18n*` / `t('key')`.

## Versioning / release

- `APP_VERSION` in `convertisseur.html` is the single version source; it must equal the newest git tag (format `vX.Y.Z`). Between a bump and the tag, `test_page.py` fails on purpose; CI checks out with `fetch-depth: 0` so this check really runs.
- Release flow: bump `APP_VERSION` → `python gen_version.py` → new `## vX.Y.Z` section in `CHANGELOG.md` → commit `Release vX.Y.Z : ...` → tag `vX.Y.Z`. User-visible changes also belong in `README.md` (French).
- Release notes: on Windows, `gh release create/edit --notes-file` mangles UTF-8 (every non-ASCII byte becomes `?`, silently). Publish them through the API instead (`PATCH /repos/{owner}/{repo}/releases/{id}` with a UTF-8 JSON body) or keep them ASCII.
- Store package (Chrome Web Store / Edge): `python build_extension.py` → `dist/ConvertisseurClavier-extension-X.Y.Z.zip` (contents of `extension/`, `manifest.json` at the root, deterministic zip); bump `APP_VERSION` for every upload, the store refuses a version it already has. Listing texts and the permission justifications to paste live in `store/` (`store/checklist.md` walks through the submission). The privacy policy is `PRIVACY.md` plus the GitHub Pages page `confidentialite.html` (https://28-create.github.io/convertisseur-clavier/confidentialite.html); `test_store.py` pins the manifest limits, the listing texts, the zip layout and the fact that the page loads nothing from the network.
- Build (Windows only): `pip install pywebview pyinstaller` then `python build_exe.py` → `dist/ConvertisseurClavier-X.Y.Z.exe` (gitignored; WebView2 required; embeds `convertisseur.html`, `fix-presse-papiers.py` + `app.ico`). `python app.py` runs the page in a native window. Cannot be built or run on Linux.

## Platform conventions

- `*.bat` and `*.ps1` must keep CRLF (`.gitattributes`); everything else is LF. Do not renormalize.
- Comments and console output in `.py` / `.ps1` / `.bat` stay ASCII (Windows cp1252/cp1255 consoles crash on Hebrew/accents); non-ASCII is reserved for data, UI strings and the HTML.
- Two installer scripts, easy to confuse: `installer.ps1` (real install: Start Menu + `Ctrl+Alt+K` + `Ctrl+Alt+H` clipboard hotkey + Explorer context menu + uninstall entry + watcher autostart) vs `installer-raccourci.ps1` (desktop shortcut only, `Ctrl+Alt+H`). `desinstaller.ps1` mirrors `installer.ps1` (context menu, watcher stop and Run value included). The Explorer context menu lives in HKCU (`Software\Classes\*\shell\ConvertisseurClavier`, `SystemFileAssociations\.txt\shell\…`, `Directory\shell\…`, `Directory\Background\shell\…`) so no admin is needed; `installer.ps1 -SansMenuContextuel` skips it, `-SansSurveillance` skips the watcher, `-SansDemarrage` installs it without launching it (sandbox test).
- The watcher autostart is the HKCU value `Software\Microsoft\Windows\CurrentVersion\Run\ConvertisseurClavier` = `"<app>\ConvertisseurClavier.exe" --paste-watch`. Updates/uninstall must stop the old watcher first (`--paste-stop`) or the exe stays locked.
- `installer.iss` (Inno Setup 6) builds `Setup_ConvertisseurClavier-X.Y.Z.exe`: wizard, per-user install (no admin), Start Menu + two hotkeys + optional context-menu task + optional watcher autostart (`surveillance` task, Run value, `[UninstallRun]`, `PrepareToInstall` stops the old watcher). `python build_setup.py` compiles; `--check` validates without Inno (used in CI).
- Context menu can only cover the Explorer (files/folders); Word, browsers and the search bar own their own menus. Universal text conversion is the clipboard hotkey: select, `Ctrl+C`, `Ctrl+Alt+H` (the exe converts the clipboard itself, no Python needed), `Ctrl+V`. The optional watcher shortens this to `Ctrl+V` with a proposal popup (Enter = convert, Shift+Enter = original, Esc = cancel). The popup has no auto-close timer: it stays until an explicit choice or a click elsewhere; a click elsewhere is a `dismiss` that leaves the proposal available for the next `Ctrl+V`, while Annuler/Esc consumes it. The browser extension (`extension/`) adds a real right-click inside web pages (`input`, `textarea`, contenteditable, any selection) plus `Ctrl+Shift+H`; it is loaded unpacked in Chrome/Edge and is not on the Web Store.
- `test_installer.ps1` is the end-to-end installer sandbox test (Windows only): `powershell -NoProfile -ExecutionPolicy Bypass -File test_installer.ps1`. It pins the watcher Run value (with a test-only value name) and its removal on uninstall.
- CI (`.github/workflows/tests.yml`) runs `test_maps.py` + `test_app.py` + `test_paste.py` + `test_extension.py` + `test_store.py` + `test_page.py` on Ubuntu + Windows with Python 3.11–3.14, and the installer test once on Windows (Python 3.12).
